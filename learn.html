Learn the Tree Structures

This page explains the tree structures used in the visualizer and how their main operations work.

Binary Search Tree

A Binary Search Tree stores values according to the rule: smaller values go to the left subtree and larger values go to the right subtree. 

        50
       /  \
     30    70
    / \    / \
  20  40  60  80
Try BST example

Insert

To insert a value, start at the root and compare the new value with the current node.

If the value is smaller, move left. If it is larger, move right. Continue until an empty child position is found.

Search

Searching uses the same comparisons. At each node, the BST ordering rule tells us which subtree can contain the value. 

Search for 40:

50 → 40 is smaller → go left
30 → 40 is larger  → go right
40 → found

Delete

Deletion depends on how many children the node has:

0 children → remove the node directly.
1 child → replace the node with its child.
2 children → replace its value with the in-order successor.

The in-order successor is the smallest value in the right subtree.

AVL Tree

An AVL tree is a Binary Search Tree that also keeps itself balanced. Each node stores its height, which is used to calculate a balance factor.

In this project, the balance factor is:

      balance factor = height(left) - height(right)

A node is considered balanced when its balance factor is -1, 0 or 1.

Why balancing is needed

A normal BST can become very unbalanced if values are inserted in sorted order.

      10
        \
         20
           \
            30
              \
               40

In this case, searching behaves more like searching through a linked list than through a balanced tree.

Rotations

AVL trees restore balance using rotations. There are four possible imbalance cases.

LL case

      Before:              After:
      
          30                  20
         /                   /  \
        20                 10    30
       /
      10

The tree is left-heavy, so a single right rotation is used.

Try LL example

RR case

      Before:              After:
      
      10                     20
        \                   /  \
         20               10    30
           \
            30

The tree is right-heavy, so a single left rotation is used.

Try RR example

LR case

      Before:              After:
      
          30                  20
         /                   /  \
        10                 10    30
          \
           20

First rotate the left child to the left, then rotate the unbalanced node to the right.

Try LR example

RL case

      Before:              After:
      
      10                     20
        \                   /  \
         30               10    30
        /
      20

First rotate the right child to the right, then rotate the unbalanced node to the left.

Try RL example

Insert

Insertion begins like a normal BST insertion. While the recursive calls return toward the root, the height of each node is updated and its balance factor is checked.

If a node becomes unbalanced, one of the rotation cases above is used to restore the AVL property.

Search

Search works exactly like in a normal BST because AVL rotations preserve the Binary Search Tree ordering property.

Delete

Deletion first follows the normal BST deletion rules. After a node is removed, heights are updated while returning through the recursive calls.

If deletion causes a node to become unbalanced, the same rotation logic is used to restore balance.

Treap

A Treap combines two different tree properties:

1. Binary Search Tree ordering by value.
2. Max-heap ordering by priority. 

      BST rule:
      left.value < node.value < right.value
      
      Heap rule:
      parent.priority >= child.priority

Each node receives a randomly generated priority when it is created. The values determine where nodes belong according to the BST rule, while priorities influence the shape of the tree.

Example

             50 (p:90)
            /         \
       30 (p:70)    70 (p:60)

The values satisfy the BST ordering rule, while the priorities satisfy the max-heap rule because each parent has a priority greater than or equal to its children.

Try Treap example

OBS: Because Treap priorities are generated randomly, the exact shape of this example may change each time it is opened.

Insert

Insertion first works like a normal BST insertion. The new value is placed according to the BST ordering rule.

After insertion, the priority of the new node is compared with the priority of its parent.

If the child has a higher priority than the parent, the heap property is violated and a rotation is used to move the child upward. 

      Before rotation:
      
            50 (p:40)
           /
       30 (p:80)
      
      
      After right rotation:
      
         30 (p:80)
              \
              50 (p:40)

The rotation keeps the BST ordering property while restoring the max-heap priority property.

Search

Search works exactly like in a normal Binary Search Tree.

Priorities are not used when searching. They only influence the shape of the tree. Search direction is determined entirely by comparing values. 

      Search for 70:
      
      50 → 70 is larger → go right
      70 → found

Delete

Searching for the node to delete again follows normal BST ordering.

A node with zero or one child can be removed directly.

If the node has two children, the child with the higher priority is rotated upward. This moves the node we want to delete one level downward while preserving the heap property.

The process continues until the target node has at most one child, after which it can be removed directly. 

      Delete 50:
      
             50
            /  \
          30    70
      
      Higher-priority child moves up
      using a rotation.
      
      The target node moves downward
      until it can be removed.

AVL vs Treap

Both AVL trees and Treaps use rotations, but for different reasons:

      AVL:
      rotation → restore height balance
      
      Treap:
      rotation → restore priority heap property

Comparison

All three structures use the Binary Search Tree ordering rule, but they differ in how they control the shape of the tree.

Structure Main rule Balancing Typical search Worst-case search
BST Left < Node < Right None O(log n) O(n)
AVL BST + balance factor Height-based rotations O(log n) O(log n)
Treap BST + heap priority Priority-based rotations Expected O(log n) O(n)

Main idea

      BST   → no balancing
      
      AVL   → deterministic balancing using height
      
      Treap → randomized balancing using priority
